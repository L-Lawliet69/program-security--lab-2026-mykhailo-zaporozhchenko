# Бізнес-логіка модуля Gameplay (Ігровий процес 1v1)

> Модуль: `Gameplay`. Відповідає за перебіг онлайн-матчу 1v1 (серії пенальті) між двома друзями на ПК у середовищі **Unity (C#)**: жеребкування черги, організацію 5 обов'язкових раундів (10 ударів), вибір 3 напрямків (`Left`, `Center`, `Right`), визначення голів/сейвів, захист від сніфінгу ходів та фіксацію нічиєї (`Draw`). Побудований на **простому C# ООП без використання Domain-Driven Design (DDD)**.

---

## 1. Призначення модуля

Модуль `Gameplay` забезпечує:
1. **Ініціалізацію матчу:** створення сесії матчу між двома гравцями (хостом і клієнтом).
2. **Жеребкування першого удару (CSPRNG):** криптографічно безпечний кидок монети перед першим раундом для визначення першого стрільця.
3. **Проведення 5 раундів (10 ударів сумарно):** кожен гравець обов'язково завдає по 5 ударів по черзі (спочатку гравець А б'є, гравець Б захищає; потім гравець Б б'є, гравець А захищає).
4. **Вибір 3 напрямків:** вибір напрямку удару стрільцем та напрямку стрибка воротарем (`Left`, `Center`, `Right`).
5. **Розрахунок голу чи сейву:**
   - Якщо напрямки однакові $\rightarrow$ воротар парирував (**Сейв**).
   - Якщо напрямки різні $\rightarrow$ м'яч залетів у ворота (**Гол**).
6. **Прихований одночасний ввід (Anti-Sniffing):** захист від перехоплення ходу суперника по мережі до моменту розкриття обох рішень.
7. **Обов'язковість 10 ударів:** заборона дострокового завершення гри при математичному відриві (для чесного обліку статистики голів).
8. **Визначення підсумку та нічия (`Draw`):** при рівному рахунку після 10 ударів фіксується нічия, обом гравцям нараховується по +1 очку в таблицю лідерів.

## 2. Моделі даних та Enums (C#)

```csharp
public enum Direction
{
    Left = 0,
    Center = 1,
    Right = 2
}

public enum ShotResult
{
    Saved = 0,
    Goal = 1
}

public enum MatchOutcome
{
    InProgress,
    PlayerAWon,
    PlayerBWon,
    Draw
}

public enum MatchState
{
    WaitingForPlayers,
    CoinToss,
    WaitingForTurnInput,
    ResolvingTurn,
    Completed
}
```

### 2.1. Клас `ShotRecord` (Запис про удар)
- `int RoundNumber` — номер поточного раунду (1..5).
- `int ShotIndex` — номер удару в матчі (1..10).
- `string ShooterId` — ідентифікатор гравця, що пробиває.
- `string KeeperId` — ідентифікатор гравця на воротах.
- `Direction ShotDir` — напрямок удару.
- `Direction DiveDir` — напрямок стрибка воротаря.
- `ShotResult Result` — результат удару (`Goal` або `Saved`).

### 2.2. Клас `MatchSession` (Сесія матчу)
- `string MatchId` — ID матчу.
- `string PlayerAId` — ID гравця А (Хост).
- `string PlayerBId` — ID гравця Б (Клієнт).
- `string FirstShooterId` — ID гравця, який виграв жереб.
- `int CurrentRound` — поточний раунд (1..5).
- `int TotalShotsTaken` — кількість виконаних ударів (0..10).
- `int ScoreA` — кількість голів гравця А.
- `int ScoreB` — кількість голів гравця Б.
- `List<ShotRecord> History` — список виконаних ударів.
- `MatchState State` — поточний стан матчу.
- `MatchOutcome Outcome` — підсумковий результат.

## 3. Логіка виконання та правила

### 3.1. Жеребкування (Coin Toss)
Перед початком матчу викликається CSPRNG генератор:
```csharp
public static bool CoinToss()
{
    using var rng = System.Security.Cryptography.RandomNumberGenerator.Create();
    byte[] b = new byte[1];
    rng.GetBytes(b);
    return (b[0] % 2) == 0;
}
```
Якщо випало `true` — першим б'є Гравець А, якщо `false` — Гравець Б.

### 3.2. Розрахунок окремого удару
```csharp
public static ShotResult ResolveShot(Direction shot, Direction dive)
{
    return (shot == dive) ? ShotResult.Saved : ShotResult.Goal;
}
```

### 3.3. Керування раундами та зміна ролей
- У кожному раунді виконується 2 удари:
  - Удар 1: Стрілець 1 б'є $\rightarrow$ Воротар 1 захищає.
  - Удар 2: Стрілець 2 б'є $\rightarrow$ Воротар 2 захищає.
- Всього відбувається 5 раундів $\times$ 2 удари = **10 ударів**.
- Доки `TotalShotsTaken < 10`, матч не може бути завершений.

### 3.4. Підбиття підсумків та нічия
Після завершення 10-го удару:
- Якщо `ScoreA > ScoreB` $\rightarrow$ `Outcome = MatchOutcome.PlayerAWon` (+3 очки Гравцю А).
- Якщо `ScoreB > ScoreA` $\rightarrow$ `Outcome = MatchOutcome.PlayerBWon` (+3 очки Гравцю Б).
- Якщо `ScoreA == ScoreB` $\rightarrow$ `Outcome = MatchOutcome.Draw` (по +1 очку обом гравцям, `Draws += 1`).

## 4. Послідовність перебігу гри

1. **Підключення друзів:** гравець А створює кімнату (хост), гравець Б підключається (клієнт).
2. **Жереб:** хост розігрує монету та надсилає клієнту інформацію про чергу першого удару.
3. **Ігровий цикл (10 ударів):**
   - Вмикається таймер на 10 секунд.
   - Стрілець обирає напрямок на клавіатурі чи мишею.
   - Воротар обирає напрямок стрибка.
   - Хост зберігає обидва вибори приховано.
   - Отримавши обидва вибори, хост викликає `ResolveShot()`, оновлює рахунок та одночасно надсилає результат обом клієнтам.
   - На екранах обох гравців одночасно програється анімація польоту м'яча та сейву/голу.
   - Гравці міняються ролями (той, хто бив, стає воротарем).
4. **Фінал:** після 10-го удару виводиться фінальний екран з переможцем або нічиєю, а статистика записується в локальний файл / таблицю лідерів.
