# Бізнес-логіка та ігрові правила — Freekick (PC Unity C#)

> Документ описує правила предметної області, ігрові механіки та логіку взаємодії онлайн-гри **«Freekick»**. Логіка побудована за **простою та зрозумілою об'єктно-орієнтованою моделлю (ООП на C#)** у середовищі Unity без зайвих ускладнень, оскільки гра розробляється як любительський проект під ПК для гри з друзями та здачі лабораторної роботи.

---

## 1. Призначення та загальні правила гри

Система реалізує міні-гру у футбол: **дуель післяматчевих пенальті 1 на 1**:
1. **Реєстрація та вхід:** гравець створює локальний або мережевий акаунт (email, нікнейм, пароль). Нікнейм є унікальним без урахування регістру (наприклад, `Alex` і `alex` — це один нік). Пароль захищається надійним криптографічним хешем (Argon2id або PBKDF2).
2. **Профіль та вибір героя:** у правому верхньому куті вікна гри відображається віджет гравця (нікнейм, іконка персонажа). Гравець може відкрити каталог аніме («Blue Lock», «Captain Tsubasa», «Inazuma Eleven» тощо), переглянути список героїв та обрати свого улюбленого персонажа.
3. **Жеребкування (Coin Toss):** на початку матчу за допомогою безпечного рандому (CSPRNG) визначається, хто б'є першим (Стрілець), а хто захищає ворота (Воротар).
4. **Структура матчу — 5 обов'язкових раундів (10 ударів сумарно):**
   - У кожному раунді обидва гравці роблять по 1 удару по черзі (спочатку гравець 1 б'є, гравець 2 ловить; потім гравець 2 б'є, гравець 1 ловить).
   - Всього кожен гравець завдає **рівно 5 ударів** (разом 10 ударів за матч).
   - **Обов'язкове правило:** матч ніколи не завершується достроково, навіть якщо одна сторона веде 3:0 після 3-го раунду. Обидва гравці пробивають усі 5 ударів для чесної та повної статистики забитих і пропущених м'ячів.
5. **Механіка 3 напрямків:**
   - Стрілець і Воротар одночасно обирають один із 3 напрямків: `Left` (вліво), `Center` (по центру), `Right` (вправо).
   - Якщо напрямки збіглися (`shot == dive`) $\rightarrow$ воротар відбив м'яч (**Сейв**, гол не зараховується).
   - Якщо напрямки не збіглися (`shot != dive`) $\rightarrow$ м'яч у сітці (**Гол**, стрільцю додається +1 очко).
6. **Захист від сніфінгу (Commit-Reveal):** хост або сервер приймає вибори гравців приховано. Гравець-воротар не дізнається про вибір стрільця через мережу, поки сам не зробить вибір (захист від читання пакетів у Wireshark).
7. **Фіксація результату та сценарій нічиєї (`Draw`):**
   - Якщо після 10 ударів `scoreA > scoreB` $\rightarrow$ перемога гравця А (+3 очки в рейтинг).
   - Якщо після 10 ударів `scoreB > scoreA` $\rightarrow$ перемога гравця Б (+3 очки в рейтинг).
   - Якщо рахунок рівний (`scoreA == scoreB`, наприклад 2:2, 3:3) $\rightarrow$ фіксується **Нічия** (`Draw`). Обом гравцям зараховується нічия і нараховується по **+1 очку** в таблицю лідерів.
8. **Таблиця лідерів (Leaderboard):** збереження статистики спільних дуелей між друзями: зіграні матчі, перемоги, поразки, нічиї, забиті голи, пропущені голи, рейтингові очки ($3 \times \text{перемоги} + 1 \times \text{нічиї}$).

## 2. Основні моделі даних (C# класи та структури)

У проекті використовуються прості C# класи, структури та моделі даних:

```csharp
// Переліки (Enums) для простої типізації
public enum Direction
{
    Left = 0,
    Center = 1,
    Right = 2
}

public enum ShotResult
{
    Saved = 0,
    Goal = 1
}

public enum MatchOutcome
{
    InProgress,
    PlayerAWon,
    PlayerBWon,
    Draw
}

public enum MatchState
{
    LobbyWaiting,
    CoinToss,
    WaitingForInput,
    TurnResolved,
    MatchFinished
}
```

### 2.1. Клас `PlayerProfile` (Профіль користувача)
- `string Id` — унікальний ідентифікатор гравця (GUID або числовий ID).
- `string Nickname` — нікнейм (3–20 символів, унікальний без урахування регістру).
- `string Email` — електронна пошта гравця.
- `string PasswordHash` — криптографічний хеш пароля (Argon2id або PBKDF2) з сіллю.
- `string ActiveCharacterId` — ID обраного аніме-персонажа.

### 2.2. Класи `AnimeTitle` та `AnimeCharacter` (Каталог персонажів)
- `class AnimeTitle`:
  - `string Id` — ідентифікатор тайтлу.
  - `string Name` — назва аніме (наприклад, «Blue Lock», «Captain Tsubasa»).
  - `List<AnimeCharacter> Characters` — список персонажів даного тайтлу.
- `class AnimeCharacter`:
  - `string Id` — ідентифікатор персонажа.
  - `string Name` — ім'я (наприклад, «Isagi Yoichi», «Tsubasa Ozora»).
  - `string TitleId` — прив'язка до тайтлу.
  - `string IconPath` — шлях до аватарки у папці Resources/Sprites.

### 2.3. Клас `ShotRecord` (Запис про окремий удар)
- `int RoundNumber` — номер раунду (від 1 до 5).
- `int ShotIndex` — порядковий номер удару в матчі (від 1 до 10).
- `string ShooterId` — хто завдавав удар.
- `string KeeperId` — хто стояв на воротах.
- `Direction ShotDir` — напрямок удару (`Left`, `Center`, `Right`).
- `Direction DiveDir` — напрямок стрибка воротаря (`Left`, `Center`, `Right`).
- `ShotResult Result` — результат (`Goal` або `Saved`).

### 2.4. Клас `MatchSession` (Ігровий матч)
- `string MatchId` — ідентифікатор матчу.
- `PlayerProfile PlayerA` — дані першого гравця.
- `PlayerProfile PlayerB` — дані другого гравця.
- `string FirstShooterId` — ID гравця, який виграв жереб і б'є першим.
- `int CurrentRound` — поточний раунд (1..5).
- `int TotalShotsTaken` — лічильник виконаних ударів (0..10).
- `int ScoreA` — кількість голів гравця А.
- `int ScoreB` — кількість голів гравця Б.
- `List<ShotRecord> ShotsHistory` — історія всіх виконаних ударів.
- `MatchState State` — поточний стан гри.
- `MatchOutcome Outcome` — фінальний результат матчу.

### 2.5. Клас `LeaderboardEntry` (Рядок рейтингової таблиці)
- `string Nickname` — нікнейм гравця.
- `int MatchesPlayed` — зіграно матчів.
- `int Wins` — перемоги.
- `int Losses` — поразки.
- `int Draws` — нічиї.
- `int GoalsScored` — забиті голи.
- `int GoalsConceded` — пропущені голи.
- `int Points` — турнірні очки ($3 \times \text{Wins} + 1 \times \text{Draws}$).

## 3. Основні контролери та методи бізнес-логіки

Замість складних Use Cases та CQRS команд використовуються прості C# класи-сервіси з прямими зрозумілими методами.

### 3.1. Ігровий двигун (`PenaltyEngine.cs`)
Звичайний C# клас, який не залежить від Unity UI та легко покривається юніт-тестами:

```csharp
public static class PenaltyEngine
{
    // Порівняння напрямків: однаковий -> сейв, різний -> гол
    public static ShotResult ResolveShot(Direction shot, Direction dive)
    {
        return (shot == dive) ? ShotResult.Saved : ShotResult.Goal;
    }

    // Визначення переможця після завершення 10 ударів
    public static MatchOutcome DetermineOutcome(int scoreA, int scoreB)
    {
        if (scoreA > scoreB) return MatchOutcome.PlayerAWon;
        if (scoreB > scoreA) return MatchOutcome.PlayerBWon;
        return MatchOutcome.Draw;
    }

    // Жеребкування черги першого удару (CSPRNG 50/50)
    public static bool CoinToss()
    {
        using var rng = System.Security.Cryptography.RandomNumberGenerator.Create();
        byte[] bytes = new byte[1];
        rng.GetBytes(bytes);
        return (bytes[0] % 2) == 0;
    }
}
```

### 3.2. Контролер матчу (`MatchController.cs`)
Керує станом гри та перевіряє правила:
- `void StartMatch(PlayerProfile p1, PlayerProfile p2)` — ініціалізує матч, проводить жеребкування черги першого удару, встановлює раунд 1.
- `bool SubmitPlayerInput(string playerId, Direction direction)` — фіксує вибір гравця на хості. Якщо отримано вибори від обох учасників (стрільця і воротаря), викликає розрахунок результату.
- `void ResolveCurrentTurn()`:
  - Порівнює вибори через `PenaltyEngine.ResolveShot()`.
  - Оновлює рахунок `ScoreA` або `ScoreB`.
  - Додає запис до `ShotsHistory`.
  - Збільшує `TotalShotsTaken`.
  - Якщо `TotalShotsTaken == 10` $\rightarrow$ завершує матч (`State = MatchFinished`), визначає результат (`DetermineOutcome`) та надсилає статистику в таблицю лідерів.
  - Якщо `TotalShotsTaken < 10` $\rightarrow$ міняє ролі стрільця та воротаря місцями і починає наступний удар.

## 4. Сценарій нічиєї (Draw Flow)

Коли обидва гравці пробили всі свої 5 ударів (загалом 10), рахунок може виявитися рівним (наприклад, 1:1, 2:2, 3:3 тощо).

1. **Фіксація:** Контролер матчу фіксує `Outcome = MatchOutcome.Draw`.
2. **Оновлення статистики:**
   - Обом гравцям додається:
     - `MatchesPlayed += 1`
     - `Draws += 1`
     - `Points += 1`
     - `GoalsScored += Score`
     - `GoalsConceded += Score`
   - Жодному з гравців не зараховується поразка.
3. **Відображення на екрані:**
   - Показується фінальний екран «Нічия!» з підсумковим рахунком.
   - Обидва персонажі відтворюють анімацію поваги / потиску рук.

## 5. Аутентифікація та збереження даних

- **Сервіс `AuthService.cs`:**
  - `bool Register(string email, string nickname, string password)` — валідує регулярним виразом нікнейм, перевіряє унікальність `nickname.ToLowerInvariant()`, хешує пароль і зберігає акаунт.
  - `bool Login(string login, string password)` — знаходить користувача та верифікує пароль проти збереженого хешу.
- **Сервіс збережень `SaveManager.cs`:**
  - Записує збереження у файл `save.json` або локальну базу SQLite у папці `Application.persistentDataPath`.
  - Для виконання вимог лабораторної роботи з безпеки додає до збережених даних HMAC-SHA256 підпис. Якщо файл змінено зовні у блокноті, додаток виявляє порушення цілісності та повідомляє про помилку.
